This document describes the full database schema used by Atomic CRM. The schema is defined declaratively in `supabase/schemas/` (source of truth) and applied via migrations in `supabase/migrations/`.

## Views

### companies_summary

Extends `companies` with aggregated deal and contact counts.

```sql
SELECT
    c.*,
    count(distinct d.id) AS nb_deals,
    count(distinct co.id) AS nb_contacts
FROM companies c
    LEFT JOIN deals d ON c.id = d.company_id
    LEFT JOIN contacts co ON c.id = co.company_id
GROUP BY c.id;
```

### contacts_summary

Extends `contacts` with company name, task count, and full-text search fields.

```sql
SELECT
    co.*,
    jsonb_path_query_array(co.email_jsonb, '$[*]."email"')::text AS email_fts,
    jsonb_path_query_array(co.phone_jsonb, '$[*]."number"')::text AS phone_fts,
    c.name AS company_name,
    count(distinct t.id) FILTER (WHERE t.done_date IS NULL) AS nb_tasks
FROM contacts co
    LEFT JOIN tasks t ON co.id = t.contact_id
    LEFT JOIN companies c ON co.company_id = c.id
GROUP BY co.id, c.name;
```

The `email_fts` and `phone_fts` columns are text arrays derived from the JSONB columns, used for full-text search filtering.

### activity_log

Aggregates creation events from companies, contacts, contact notes, deals, and deal notes into a single pageable list. Used for the activity feed on the dashboard.

Each row contains an `id` (e.g. `company.42.created`), a `type`, a `date`, and the relevant entity as a JSON object (only one of `company`, `contact`, `deal`, `contact_note`, `deal_note` is non-null per row).

### init_state

A simple view that returns whether the CRM has been initialized (has any sales records). Uses `security_invoker = off` so it can be queried without authentication.

```sql
SELECT count(id) AS is_initialized
FROM sales
LIMIT 1;
```

## Triggers

Triggers automatically run functions on insert/update:

- **`set_*_sales_id_trigger`**: On insert to `companies`, `contacts`, `contact_notes`, `deals`, `deal_notes`, or `tasks`, auto-populates `sales_id` from the current authenticated user if not provided.
- **`company_saved`**: On insert or update to `companies`, auto-fetches the company logo from the website's favicon.
- **`lowercase_contact_emails`**: On insert or update to `contacts`, lowercases email addresses in `email_jsonb`.
- **`contact_saved`**: On insert or update to `contacts`, auto-fetches the contact avatar from their email address.
- **`on_public_contact_notes_created_or_updated`**: After insert to `contact_notes`, updates the contact's `last_seen` timestamp.
- **`on_*_attachments_updated_delete_note_attachments`**: After update/delete to `contact_notes` or `deal_notes`, cleans up deleted attachment files from storage.
- **`on_auth_user_created`** / **`on_auth_user_updated`**: After insert/update to `auth.users`, syncs user data to the `sales` table.

| Bucket | Public | Purpose |

Authenticated users can select, insert, and delete objects in the `attachments` bucket. Files are stored under paths like `{note_id}/{filename}`.

## Row Level Security

All tables have RLS enabled. Policies follow a consistent pattern:

| Table | SELECT | INSERT | UPDATE | DELETE |
|-------|--------|--------|--------|--------|
| `companies` | All authenticated | All authenticated | All authenticated | All authenticated |
| `contacts` | All authenticated | All authenticated | All authenticated | All authenticated |
| `contact_notes` | All authenticated | All authenticated | All authenticated | All authenticated |
| `deals` | All authenticated | All authenticated | All authenticated | All authenticated |
| `deal_notes` | All authenticated | All authenticated | All authenticated | All authenticated |
| `sales` | All authenticated | *See note* | *See note* | None |
| `tags` | All authenticated | All authenticated | All authenticated | All authenticated |
| `tasks` | All authenticated | All authenticated | All authenticated | All authenticated |
| `configuration` | All authenticated | Admin only | Admin only | None |

:::note
The `sales` table has restricted insert/update policies. New sales records are created by the `on_auth_user_created` trigger (which runs as `security definer`), not by regular user inserts. Direct inserts and updates to `sales` are handled by edge functions with elevated privileges.
:::

## Important Notes

### Primary Keys Are Integer, Not UUID

All tables use `bigint generated by default as identity` for primary keys (auto-incrementing integers). The only UUID in the schema is `sales.user_id`, which references `auth.users(id)`.

### Email and Phone Are JSONB

The `contacts` table stores email addresses and phone numbers as JSONB arrays, not as plain text columns. This allows multiple emails and phones per contact with type labels.

**Email format:**
```json
[
  { "email": "jane@example.com", "type": "Work" },
  { "email": "jane@personal.com", "type": "Personal" }
]
```

**Phone format:**
```json
[
  { "number": "+1-555-0100", "type": "Mobile" },
  { "number": "+1-555-0200", "type": "Work" }
]
```

The old plain-text `email`, `phone_1_number`, `phone_1_type`, `phone_2_number`, `phone_2_type` columns were dropped in earlier migrations and replaced by the JSONB columns.

### sales_id Is Automatically Set

The `sales_id` foreign key on `companies`, `contacts`, `contact_notes`, `deals`, `deal_notes`, and `tasks` is automatically populated from the current authenticated user via a trigger. You do not need to provide it when creating records.

### DELETE Returns 204

PostgREST DELETE requests return HTTP 204 (No Content) on success, not 200. The response body is empty.

### PostgREST Returns Arrays

All GET requests to PostgREST return arrays, even when querying for a single record by ID. To get a single object, either:
- Use the `Accept: application/vnd.pgrst.object+json` header, or
- Access the first element of the returned array in your client code.

### Configuration Values Use Slugs

Values stored in the `configuration` table (sectors, deal categories, task types, note statuses) use slugs (lowercase, hyphen-separated) as `value` fields, not display labels. For example, `"copywriting"` not `"Copywriting"`.
